# Thebes integration

Everything Proofly's UI knows about the chain lives in this directory. Nothing
above it — no page, no component — imports a chain type or knows what a contract
id is.

## The layers

| File | Responsibility |
| --- | --- |
| `config.ts` | Where the contracts are. Both ids are baked at build time from `thebes.toml` by `scripts/build-frontend.sh`, so nothing here can drift from what was deployed. |
| `boundary.ts` | Transport. `POST /api/query`, `GET /api/next_nonce`, `POST /api/call`, `GET /api/receipt` — plus the retry rules that make a fanned-out validator set feel reliable. |
| `candid.ts` | The wire format. Proofly's own Candid encoder and decoder — no third-party codec. |
| `idl.ts` | Proofly's Candid interface, mirrored from `backend/backend.did`. |
| `memphis.ts` | Identity. A typed face over the vendored Memphis runtime: sign in, restore, renew, sign out. |
| `actor.ts` | The seam the pages use. Method names, arguments and return shapes are exactly what they have always been. |

`useThebesActor()` in `src/hooks` is the React face of `actor.ts`; it rebuilds
the handle whenever the Memphis session changes, so a call is never made with a
stale token.

## Three things that are easy to get wrong

**A query cannot verify a session.** Checking a Memphis token is an
inter-contract call, and queries cannot make one — so every user-scoped read is
an `update`, and pays a consensus round. That is why the company list is not as
instant as a cached read would be. It is not a bug to optimise away by moving
the check client-side; the check is the security.

**The transport sender is not an identity.** `boundary.ts` keeps a random
per-browser sender so the substrate can sequence this browser's updates by
nonce. Nobody signs with it and the contract keys nothing on it. Who the user
*is* comes from their Memphis session token, which travels as an ordinary
argument.

**Sign-in cannot run on localhost.** A WebAuthn credential is bound to a
relying-party id, and a page may only claim an RP id that is a suffix of its own
origin — so the passkey ceremony only works when the app is served from the
Memphis origin, which is where `thebes-deploy deploy` puts it. `canSignIn()`
reports this, so the UI can say so rather than failing mysteriously. Everything
else works locally.

## Changing the contract's interface

1. Edit `backend/src/lib.rs`.
2. `cargo build --release --target wasm32-unknown-unknown --manifest-path backend/Cargo.toml`
3. `candid-extractor target/wasm32-unknown-unknown/release/backend.wasm > backend/backend.did`
4. Mirror the diff into `idl.ts`. The `.did` generated from the wasm is the
   authority; this file follows it.
5. Regenerate the golden vectors if the wire shapes changed, and re-run
   `npm run check:codec`.

## The Candid codec is ours

Candid is Thebes' wire format: the substrate speaks it and `thebes-deploy`
speaks it. `candid.ts` is Proofly's own implementation of the slice this
interface uses — `text`, `nat8`, `nat64`, `null`, `vec`, `record`, `variant`.
Anything outside that slice throws rather than guessing.

It replaced a third-party Candid package — the app's last dependency from
another chain's ecosystem, and deprecated by its own maintainers besides. The
codec is not trusted on its own word: `scripts/candid-fixtures.json` holds byte
vectors generated by the reference implementation before it was removed, and
`npm run check:codec` asserts this codec reproduces them **byte for byte** and
decodes them back to the same values, plus six malformed inputs it must reject.

    cd frontend && npm run check:codec
